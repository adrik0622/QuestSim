## What works

Godot .NET low-poly 3D room, first/third-person cameras, CPU-only headless authority,
and two independently running clients. Server owns movement and presence at 20Hz;
input/snapshots run at 10Hz. Clients interpolate, without prediction.

Characters retain stable identity, inventory and experience across reconnect/server
restart. Disconnected characters are absent. Re-entry validates geometry and other
active characters. World simulation ticks pause when the last joined player leaves
and resume on join; restart does not add offline wall time. Server Ctrl-C requests
a main-thread final save. Single-writer save locking and failure handling are tested.

One green crate contains one bandage. F submits a new pickup; T replays the last
persisted request/target. Server validates actor, target and two-metre reach, saves
inventory/stock/receipt together, then acknowledges. One racing player succeeds;
retries preserve the original positive or negative result without another transfer.
T does not turn an old out-of-reach failure into a success: move closer and press F.
There is no refill, item use, drop or trade. Yellow construction module is static.

## Compatibility and implementation boundaries

Save schema / wire protocol **2**; content ID `questsim:q02-room-v1`. Rebuild both
server and clients; old wire builds are incompatible. Valid Q01 v1 saves are
validated and copied byte-for-byte to `.v1-<guid>.bak` before v2 replacement.
Migration preserves characters/items/progression, ticks and canonical geometry,
adding one supply and empty receipt history once. It never repeats on v2 reload.
Old two-field client profiles remain readable; request/target are added on pickup.
Unknown, incomplete or inconsistent saves refuse instead of silently resetting.

Important source locations:

- `src/QuestSim.Domain/SharedWorld.cs`: plain state, authority, collision/re-entry,
  TakeItem, actor-scoped GUID receipts, validation, atomic save and v1 migration.
- `src/QuestSim.Game/Session.cs`: ENet/RPC, profiles, fixed ticks, save-before-reply,
  disconnect/shutdown and opt-in test controls/status. Object decoding disabled.
- `src/QuestSim.Game/RoomView.cs`: client-only geometry, avatars, camera and F/T HUD.
- `checks/QuestSim.Checks/{AuthorityChecks,PickupChecks}.cs`: domain acceptance.
- `scripts/verify_items.py`: native race/recovery/migration; lost-ack test actually
  prevents receipt delivery using SIGSTOP on its own test processes.

Current receipt/stock validation assumes one crate, no refill and no item spending.
A successful award must remain in the recipient's inventory. A building material
or future consumption path needs an explicit compatibility/invariant decision and
checks; do not bypass validation to make a cost work. Receipts are unpruned for
this probe. Add only the concrete data/functions needed; no universal transaction,
rendering, modding or migration framework.
